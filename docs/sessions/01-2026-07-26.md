# Session 1, 2026-07-26

A condensed log of one working session, written for continuity rather than as a
designed document. Current conclusions live in [`../notes/`](../notes/); where
these disagree, the notes win.

## What this session covered

From "check `Ducks.exe`" to a working native port of all I/O. In order: unpack the
DIET compression and analyse the real code; build an emulator with a visible SDL
window; add Sound Blaster emulation; then start a second emulator subclassing the
first, replacing I/O with direct pygame calls and keeping only the game logic. The
existing emulator was kept deliberately, as the reference to trace against
whenever a result was in doubt.

Along the way: a performance investigation into menu slowdown, an own sound bank
replacing XMS so sample ids could be reversed, mouse and keyboard input, Borland's
file I/O, and finally save/load.

## Key techniques

- DIET executable compression; MZ/EXE headers, relocations, DOS load semantics.
- Unicorn x86-16 real mode (`UC_MODE_16`); `ctl_remove_cache` for hooks added
  mid-run — without it, already-translated blocks ignore the new hook.
- Capstone 16-bit disassembly; Borland Turbo C++ conventions (`push bp; mov bp,sp`,
  far calls, the `push cs; call near` idiom).
- VGA Mode X (unchained planar), sequencer map mask, CRTC start-address addressing
  units, page flipping.
- Sound Blaster DSP / 8237 DMA / IRQ5; DSP time constants (22222 Hz = `0xd3`,
  11111 Hz = `0xa6`).
- XMS / HIMEM.SYS (INT 2Fh AX=4300h/4310h), EMB allocate / realloc / move.
- High-level emulation: intercept a function at its entry, read arguments off the
  stack, return to the caller.
- BP-chain walking to find callers when static search cannot: Borland's `int86`
  patches the interrupt number in at runtime.
- numpy vectorisation — and the discovery that ctypes round-trips, not arithmetic,
  were the real bottleneck.

## What was built

- **`unpack_ducks.py`** — emulates DIET's own loader stub rather than
  reimplementing LZ77. Image extent comes from the decompression output stores,
  discriminated by *address span* (stack pushes are equally high-volume but touch
  few bytes). Relocations found differentially between two load segments: 707,
  matching the stub's `mov cx,0x2c3`.
- **`validate.py`** — the decisive test is a round trip: applying the emitted
  relocation table reproduces DIET's own output byte-for-byte (114,812 bytes).
- **`trace_dos.py`** — DOS/BIOS shim. Gained an in-memory overlay for files the
  game creates, unconditional file-operation logging, lowest-free-handle
  allocation like real DOS, and an honest `AH=43h`.
- **`emulation.py`** (renamed from `play.py` via `git mv`) — full hardware
  emulation plus SDL; the tracing reference.
- **`native.py`** — subclasses it. 19 natives at this point, across
  `NATIVE_TABLE`, `SOUND_NATIVES`, `MOUSE_NATIVES`, `KEYBOARD_NATIVES`,
  `FILE_NATIVES`, plus the `DECLINE` sentinel, `cached_read` with page
  invalidation, the profilers and the verify harness.
- **`sb.py`** — Sound Blaster DSP/DMA/IRQ model. The DMA wrap period is *not* the
  DSP interrupt period.
- **`xms.py`** — XMS driver. `AH=0Fh` takes **BX=size, DX=handle**.
- **`nsound.py`** — `SoundBank` + `NativeVoices`, 8 voices on pygame channels.
  Samples are **signed 8-bit** (XOR 0x80 for the mixer).

## Errors and fixes

- **Image extent wrong** — `SS:SP` overshoots because stack and BSS are not stored
  in a DOS EXE. Fixed by discriminating output stores by address span.
- **Mode X flicker** — `start_mult=4` against byte addressing; every other frame
  black. Fixed by deriving the unit from CRTC `0x14` bit 6 and `0x17` bit 6.
- **Port `0x3da` stall** — bit 0 runs at the ~31.5 kHz horizontal rate, not the
  frame rate; a snow-avoidance blit waits on it per word and hangs forever if it
  is driven from wall clock.
- **Right-click dead** — INT 33h `0x05`/`0x06` take BX as the button being
  queried; ignoring BX makes every button behave as one. The button mask also has
  to come from the SDL events themselves, since `pygame.mouse.get_pressed()` lags
  a press behind.
- **Silent sound, four wrong hypotheses** — DOS console output (no such calls),
  INT 29h (never used), DMA read-back, IRQ latency. The real cause was no XMS at
  all: the game stores its samples in extended memory and disables audio without
  it. Then two further self-inflicted bugs: the `AH=0Fh` BX/DX reversal, and
  raising IRQ on DMA wrap rather than on block size.
- **Audio silently missing from `native.py`** — `AudioSink` was never wired in and
  sound servicing was never sliced into its main loop.
- **Performance, two wrong hypotheses** — "the natives aren't the cost" (Mpx/s was
  saturated) and "the per-pixel loops are the cost" (numpy did not move the
  ceiling). The real cause was 417 `uc.mem_read` calls per call.
- **The verify harness sampled under 1%** — hooks added mid-run do not apply to
  already-translated blocks; `ctl_remove_cache` fixed it.
- **INT 33h static search false positive** — `eb cd` (a jump operand) followed by
  `33 c0` (an opcode) looks like `int 0x33`. There is no INT 33h in the image.
- **Arrow keys dead in the menu** — DOS's two-read extended-key protocol was not
  implemented.
- **Save error, wrong diagnosis** — monotonic handle allocation was blamed, but
  the log showed only 14 file operations and **no CREATE at all**, which disproved
  it. The real cause was `AH=43h` (get file attributes) blindly returning success,
  which told Borland's `open()` the slot already existed so it never took the
  create path. The handle-reuse change was kept as a separate genuine latent bug
  and labelled as such rather than presented as the answer.
- **No log output, twice** — `native.py` runs with `verbose=False`, silencing
  `_note`; then the summary only printed at exit. Fixed by making `_fop()` print
  unconditionally.

## What worked, as a method

**Measure, don't guess.** Every wrong hypothesis above was killed by
instrumentation rather than by argument — and each domain needed a *different*
discovery technique: a write profiler for graphics, caller-climbing for sound, the
BP chain for input, layer-tracing for files.

is the live hypothesis); ~92% of the code unidentified, essentially all game

bypasses (the loader's `x di/32` scaling *is* preserved).
