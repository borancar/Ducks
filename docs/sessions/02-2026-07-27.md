# Session 2, 2026-07-27

A condensed log of one working session, written for continuity rather than as a
designed document. Current conclusions live in [`../notes/`](../notes/); where
these disagree, the notes win.

## What this session covered

Make saves persist; then **remove every remaining `INT` instruction** — starting
with the sound loader and XMS, then the pre-game setup, floating point, and the
DOS calls; then performance work on `compose_scroll` and `draw_sprite`; then the
first moves into the drawing pipeline proper — the entity loop, the sprite
outline, and the layer caller's four-plane loop.

The strategic reframing happened here. A recommendation *against* porting
`0xaba5` on cost grounds was overruled: *"we sadly need to reverse engineer the
entire drawing code, we will eventually replace the planar with flat drawing, but
for that we need to know what we're drawing. Also note that guest CPU is running
that drawing for sprites, killing itself."* See
[drawing-port-goal](../notes/drawing-port-goal.md).

## Key techniques

- **The packed `Ducks.exe` decompresses during the main loop**, so code bytes are
  not in place at construction time. Running the unpacked image avoids the whole
  problem.
- Writing IP inside a `UC_HOOK_CODE` handler to redirect execution;
  `ctl_remove_cache` for mid-run code changes.
- **Unicorn implements x87 in real mode** — verified directly (`__ftol(3.7)=3`,
  division, `FCOMP`/`FNSTSW` C0/C3), which is what made native FP possible.
- **Borland's FP emulation encoding.** The compiler emits `FWAIT` + ESC opcode
  (`D8`–`DF`) + ModRM; the linker overwrites the two-byte `FWAIT`+ESC pair with a
  two-byte `INT`. So `INT 34h..3Bh` ↔ `D8..DF`, and `INT 3Dh` is a lone `FWAIT`.
  (`0x98` is `cbw`, which capstone renders as `cwde`.)
- Mode X planar layout: column `x` lives in plane `x & 3` at byte `x >> 2`;
  sequencer map mask via ports `0x3c4`/`0x3c5`.
- numpy `as_strided` over both source and destination;
  `np.frombuffer(bytearray)` is **writable**; `np.copyto(dst, vals, where=mask)`.
- Borland runtime internals: `_doserrno` at `DGROUP:0x2f9c`, errno table `0x2f9e`,
  `errno` `0x7f`, file-flags table `0x2f6e` (count at `0x2f6c`), 32-bit shift
  helper `0x1148` (SHR, unsigned), struct-push helper `0x11cc`, `int86` at
  `0x02909` with its worker `0x293a` building `55 CD nn 5D CB` **on the stack**.
- The Pascal convention (`ret N`, callee pops) is not modelled by the native
  dispatcher.

## What was built

- **`native.py`** — persistence (`_persist`, `_unpersist`, `_writable_host_path`,
  `flush_open_files`, `--read-only`); `install_native_xms` with a hand-written far
  return; native FP (`install_native_fp` running `FINIT` at scratch `0x800`,
  `_patch_fp_site` writing back `9B, 0xD8+intno-0x34` and rewinding IP);
  `STUBBED_INT_SITES` (23 hardcoded image offsets) with `INT_STUBS` keyed
  `(intno, ah)`; natives for DOS close/getattr/open/write, `isatty`, `ioctl`,
  `int86`, BIOS video and `setblock`; the shared vectorised compositor
  `compose_rows`; `blit_sprite` split out of `native_draw_sprite`;
  `native_particles`, `native_draw_entities`, `native_outline_sprite`,
  `set_plane`; and the first plane loop:

  ```python
  PLANE_LOOPS = {0x0CD5F: (0x0CD98, plane_loop_layer)}

  def plane_loop_layer(m):
      g = m.dgroup_base
      shared = compose_layer_shared(m)
      for plane in range(4):
          set_plane(m, plane)
          if shared is None:
              native_compose_layer(m, 0)
          else:
              compose_layer_plane(m, shared, plane)
          draw_entities(m, scene=g + 0x0D93, view=g + 0x1755, colour=0)
  ```

  with `install_plane_loops`, `_on_plane_loop` (the IP jump is
  `IP + (exit_off - head)`) and `_verify_plane_loop`, which snapshots at the loop
  head, compares at the exit, and saves/restores `map_mask`, `active_planes` and
  `[0x177d]`.
- **`find_int86.py`** — walks the frame chain from an interrupt raised outside the
  image; found `int86` and the mouse-reset caller `0x067e6`.
- **`test_retire.py`** — drives the guest's own `0x78d4` on synthetic entities and
  compares against the native. Three cases, all match.
- **`trace_dos.py`** — two correctness fixes only, each explicitly authorised: the
  honest `AH=43h`, and zero-length write meaning truncate.

## Addresses decoded

```
0x057ee set_plane        0x05761 plot_pixel (320)   0x057a1 plot_pixel (360)
0x0ab09 particles        0x0aba5 draw_entities      0x065f1 outline_sprite
0x078d4 set_entity_type  0x02909 int86              0x0293a int86 worker
0x0cd5f layer plane loop (exit 0x0cd98)   0x0e4dc scroll plane loop (exit 0x0e673)
```

- **Particle record**, 16 bytes: `+0` x dword, `+4` y dword (unsigned, 1/8 px),
  `+0xc` colour. Array far pointer at `[0x18c1]`, count at `[0x18cd]`.
- **Entity record**, 0x29 bytes: `+0` x, `+4` y dword, `+0x14` frame (signed),
  `+0x17` flag, `+0x1f` sub-index, `+0x23` y offset, `+0x25` type.
- **Sprite tables**: a far pointer per type at `DGROUP:0x9a`; a flags byte per type
  at `0x3a7` (bit 2 = mirrored variant in the next slot); facing at `[0x511]`;
  animation base at `[0x179e]`. The header at `ds:0x18e9` is the pointer *value*,
  not a pointer to it.
- **Viewport**: `[0x172d]`/`[0x172f]` top/bottom, `[0x1731]`/`[0x1733]`
  left/right, `[0x1735]` right, `[0x1739]`/`[0x173d]` scroll x/y,
  `[0x538]`/`[0x53a]` width/height.

## Errors and fixes

- **Edited `trace_dos.py` to add persistence** — rejected: the logic belongs in
  `native.py`. See [editing-conventions](../notes/editing-conventions.md).
- **`pkill -f "native.py..."` killed the shell running it** (exit 144), three
  times, because the command line contains the pattern it matches. Kill by PID, in
  a call separate from the launch.
- **`INT_SITE_CACHE` used as a default argument** before its module-level
  definition → `NameError` at import, and the game never started at all.
- **A 40-second run limit read as a crash.** Short limits quit mid-play; see
  [running-a-session](../notes/running-a-session.md).
- **Packed-versus-unpacked confusion** — byte verification of hardcoded interrupt
  sites failed because the DIET image is not decompressed at install time. Two
  contradictory explanations were asserted before the simple fix landed: run the
  unpacked exe, rather than writing deferred-verification machinery.
- **Dropped the `planes` binding** while rewriting `draw_sprite`; the verify
  harness caught it (`native raised NameError`) and ran the original body instead
  of crashing.
- **`native_bios_video` regression**, live for four commits: `trace_dos.py`'s
  do-nothing `_bios_video` was read, and `emulation.py`'s override that tracks the
  cursor was missed. Ducks reads `AH=03h` then pokes `0xb8000`. Fixed by
  delegating to `m._bios_video()`.
- **Three cases of inferring structure from broken instrumentation** — written up
  as [verification-lessons](../notes/verification-lessons.md).
- **Asked for a game state that cannot be produced on demand** (a balloon leaving
  the screen). Fixed by driving the guest's own code on synthetic input instead —
  `test_retire.py`.
- **Missing zero-length-write truncate** — save sizes vary (61/62/66 bytes), so a
  shorter save over a longer one left a stale tail.

## Results

- Save/load persistence, with the write guards.
- **26,821 → 0 interrupts executed.**
- `compose_scroll` 1178 → 311 µs and `compose_layer` 894 → 302 µs, vectorised,
  7,293 comparisons clean.
- `draw_sprite` 178 → 77 µs (7,145 comparisons).
- `plot_pixel` 627,260 → 5,020 calls, by replacing the particle loop (1,644).
- `draw_entities` native for all types with no declines; the outline implemented;
  entity retirement reproduced and unit-tested.
- The layer plane loop native (748 comparisons) and hoisted, 1471 → 839 µs (904).
- Coverage at the end: 63 named functions, 8,288 bytes, 7.2% of the image, 14.9%
  of the 423 prologues — with the caveats that the denominator includes data, that
  about half the named functions are Borland runtime rather than game code, and
  that the game's *rules* are essentially untouched.

## Believed at the time, later corrected

That the outline at `0x65f1` had **never executed** and could not be verified. It
does run in ordinary play and has since been byte-compared clean — see
[drawing-port-goal](../notes/drawing-port-goal.md). The background warp, however,
is still never seen.

About 85% of each frame is emulated guest CPU, which is why the argument for
continuing is reach rather than speed.
