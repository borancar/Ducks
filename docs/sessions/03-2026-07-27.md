## `0xbb3b` is `draw_number`

A right-aligned fixed-width decimal, drawn as digit sprites 12 pixels apart. Far
call; the caller cleans 14 bytes of arguments.

```c
void far draw_number(int value,        /* +0x06 */
                     int x,            /* +0x08 */
                     int y,            /* +0x0a, sign-extended to long */
                     void far *clip,   /* +0x0c  viewport / clip rect */
                     char colour,      /* +0x10  colour offset (0 or 0x90) */
                     int digits)       /* +0x12 */
{
    for (int i = digits - 1; i >= 0; i--) {
        int glyph = 0x71 + value % 10;
        draw_sprite(&glyph, x + i * 12, (long)y, ds:0x18e9, clip, colour);
        value /= 10;
    }
}
```

Details that matter for faithfulness: `x + i*12` is computed as `x + i*4 + i*8`;
the least significant digit is drawn first, at the **rightmost** position; `idiv`
is signed, so `/` and `%` truncate toward zero rather than flooring as Python
does; there is no leading-zero suppression, so `digits` glyphs are always drawn;
and the glyph index reaches `draw_sprite` as a far pointer to a stack word, which
is why the native can pass an index directly.

`0x0d757` is a third number drawer, same layout, but with clip, table and colour
hardcoded and glyph `0x70` tiled behind each digit.

## The scroll caller's plane loop, `0x0e4dc`–`0x0e673`

```
for plane in 0..3:                                   # byte [bp-0x1f]
    set_plane(plane)                                 # 0x57ee
    compose_scroll([0x1739], [0x173d])               # 0x5dc4
    if [0x4f6]: particles()                          # 0xab09
    draw_entities(ds:0xd6f, view ds:0x172d, 0)       # 0xaba5  x5, in this order
    draw_entities(ds:0xd63, view ds:0x172d, 0)
    draw_entities(ds:0xd7b, view ds:0x172d, 0)
    draw_entities(ds:0xd87, view ds:0x172d, 0)
    draw_entities(ds:0xd9f, view ds:0x172d, 0)
    if [bp+6] == 0:      draw_entities(ds:0xd93, view ds:0x172d, 0x90)
    if byte [0x178b]:    draw_entities(ds:0x178c, view ds:0x1741, 0x90)
    for i in 0..2:
        if byte [0x2154+i]:
            blit_rows_masked(far ptr at [0x210c+i*4], rect ds:(0x2118+i*0x14), 0)
    if [bp-8]:    draw_number([bp-6],   0x80, 0x22, ds:0x1741, 0x90, 6)
    if [bp-0xa]:  draw_number([0x2007], 0xe1, 0x22, ds:0x1741, 0x90, 2)
    y = [0x53a] - 7 - [0x2003]
    for x in [bp-2] .. [bp-4]-1:  (*[0x53e])(x, y, 0)    # a 5-pixel run
```

This is the **seven-layer scene structure**: six 12-byte scene records at
`DGROUP:0xd63`, drawn in the order 1, 0, 2, 3, 5, then 4 (`0xd93`, gated by the
function's argument, and the one the layer caller draws), plus a seventh at
`0x178c` with its own viewport. Viewports are 20-byte records: `0x172d` and
`0x1741` here, `0x1755` in the layer caller, `0x1769` for the tally.

**There are two pixel plotters, not one.** The loop calls through the pointer at
`[0x53e]`, which holds `0x5761` (stride 80) or its 360-wide twin `0x57a1` (stride
90), identical otherwise. That pointer is `0000:0000` until a level starts.

## What was built

- `native_draw_number` / `draw_number(...)` and `native_draw_number2` /
  `draw_number2(...)`, both calling `blit_sprite` directly so there is no second
  native dispatch per digit.
- Resolved-argument cores split out of the stack-reading shims, following the
  `blit_sprite` precedent: `compose_scroll(m, argx, argy)`,
  `blit_rows_masked(m, table, rect, srcrow)`, `blit_rows(m, table, rect, srcrow)`,
  `plot_pixel(m, x, y, colour, stride)`.
- `plane_loop_scroll`, `plane_loop_hud` and `plane_loop_tally`, reading their
  locals off the live frame via `m._reg(UC_X86_REG_SS) * 16 + m._reg(...BP)`.
- `compose_scroll_shared` / `compose_scroll_plane` — the hoist. The shared part
  returns `(dst, row_adv, right, mask_x, base_x, fg, bg, shifts, nrows)`, and the
  width has to cover all four planes:
  `width = max([p + 4 * (s - 1) + 1 for p, s in enumerate(spans) if s] or [0])`.
- A rewritten `find_function_start`: a bisect into a **disjoint** function map
  built by walking forward, plus `function_extent`, `_fp_normalised` (FP sites
  desync any raw linear sweep) and `test_fn_start.py` to pin all of it.
- `coverage.py`, measuring converted code against a disjoint-extent denominator.
- Crash diagnostics: `crash_report`, the wild-jump trap, the iret guard, and
  `--trace-blocks`.
- Ten flags flipped to `BooleanOptionalAction, default=True`, so playing takes no
  flags and each piece still has a `--no-` form.

## Errors and fixes

- **`[0x53e]` matched on the offset word alone** (`0x0ac1`) — it recognised
  neither plotter, so the native silently skipped all 5 pixels. `--verify` caught
  it as 5 mismatched bytes in 23 of 612 calls. Fixed by resolving the full far
  pointer.
- **An inferred segment written as fact** — "the segment sits 0x4ca paragraphs
  above the load segment", when only the offset had been observed.
- **`find_function_start` short-circuited on `cand == off`**, so any address in
  the prologue table returned itself unconfirmed. 28 of 423 prologue matches sit
  *inside* other functions, so extents overlapped and coverage claimed 123,889
  bytes "in functions" against a 100,688-byte code region. Fixed by inverting to a
  disjoint forward-walked map.
- **The convergence test was badly designed** — sweeps starting later cannot
  produce earlier boundaries, which gave a meaningless 28.4%. Redone judging each
  site only by the sweeps that could reach it: 100%, against 82.8% for the old
  scan.
- **Ground truth built from raw bytes** produced 23 phantom boundaries inside FP
  sites (e.g. `0x0044b` inside the site at `0x00449`). Fixed by generating
  boundaries from normalised bytes.
- **Coverage sampled arbitrary byte offsets** and reported 37.6% — most of those
  offsets are mid-instruction, where `None` is the correct answer.
- **A timing comparison across two sessions** appeared to show a regression
  (6046 → 6957 µs), but the control showed untouched `blit_rows` had also gone
  270 → 370 µs: the sessions were not comparable.
- **A 900-second session recorded zero comparisons** — `mode=0x03` throughout. See
  [running-a-session](../notes/running-a-session.md).
- **`find_function_start` was too slow** to finish, confirming every candidate in
  an 8 KB window; rewritten as an indexed bisect.
- **A wrong iret hypothesis**, refuted by instrument rather than argument — see
  [open-readme-crash](../notes/open-readme-crash.md).
- **`pgrep -f "run-seconds"` matched its own command line**, the same trap as the
  earlier `pkill` lesson; no session was actually running.
